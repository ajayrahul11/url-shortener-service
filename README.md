# URL Shortener Service

Build from scratch a Java / Spring Boot URL shortener service exposing three capabilities: (1) shortening, where a client submits a long URL and receives a short code/URL; (2) redirect, where requesting the short URL sends the visitor to the original long URL; and (3) click analytics, where each redirect is recorded and aggregated click data can be retrieved. The request gives no scale, retention, authentication, or analytics-depth targets, so the first version is designed as a conventional, single-region, relational-database-backed service with sensible defaults that can be adjusted later.

## Stack
Java 21 · Spring Boot 4 · PostgreSQL (Flyway) · Redis · Spring Security (API key) · Actuator · springdoc (OpenAPI + Swagger UI)

## Quick start

**1. Set the two required secrets** (use your own values; never commit them):

macOS / Linux (bash/zsh):
```bash
export DB_PASSWORD=devpass
export SHORTENER_API_KEY=my-secret-key
```
Windows (PowerShell):
```powershell
$env:DB_PASSWORD = "devpass"
$env:SHORTENER_API_KEY = "my-secret-key"
```

**2. Build and start the stack** (app on `:8080`, plus Postgres and Redis; the first build takes a few minutes):
```bash
docker compose up --build
```
It is ready when `http://localhost:8080/actuator/health` returns `{"status":"UP"}`.

**3. Try the API.** Easiest: open the Swagger UI at <http://localhost:8080/swagger-ui/index.html>, click **Authorize**,
enter your `SHORTENER_API_KEY`, then use **Try it out**. Or with curl (Windows: use `curl.exe`):
```bash
# create a short link (needs the API key)
curl -s -X POST localhost:8080/api/shorten -H "X-API-Key: my-secret-key" -H "Content-Type: application/json" \
     -d '{"url":"https://example.com/some/long/path"}'
# follow it: expect 302 with Location: https://example.com/...
curl -i localhost:8080/<shortCode>
# click analytics (eventually consistent, allow ~5 s)
curl -s localhost:8080/api/analytics/<shortCode>
```
Windows PowerShell: put the JSON in a file (`body.json`) and use `curl.exe -d "@body.json"`, or use Swagger UI.

**4. Stop.** `Ctrl+C`, then `docker compose down` (add `-v` to also delete the database volume).

## Troubleshooting
| Symptom | Fix |
|---|---|
| `set DB_PASSWORD` / `set SHORTENER_API_KEY` error from compose | export the two variables from step 1 in the same terminal |
| `port is already allocated` on 8080 | stop the other process or container using 8080 |
| `docker compose build` fails with a Maven Central 5xx | transient network error: run it again |
| `401` from `POST /api/shorten` | missing/incorrect `X-API-Key` header (Swagger: click Authorize) |
| `release version 21 not supported` when running tests | your JDK is older than 21; install it and fix `JAVA_HOME` |

## Non-functional requirements
- Redirect path uses cache-aside reads (Redis) so redirects are low-latency; Postgres is the source of truth
- Strong consistency for the short-code -> URL mapping; EVENTUAL consistency for click analytics (Redis counters, write-behind flushed asynchronously) - redirects never block on analytics writes
- Collision-free short codes via an atomic Redis counter encoded in base62
- Rate limiting per client on all endpoints (HTTP 429 with Retry-After)
- Link TTL/expiry (expired links return 410 Gone; cache TTL never exceeds remaining link lifetime)
- Input validation on every request (http/https URLs only, max length, alias pattern); errors as RFC 7807 problem details
- Authentication on all mutating endpoints (API key from environment; no secrets in code or config)
- Observability: Actuator health/metrics endpoints and structured logging
- Graceful degradation: redirects still work from Postgres when Redis is unavailable
- Dockerised: Dockerfile + docker-compose (app, Postgres, Redis) so the service runs end-to-end with one command
- Tested: unit tests, Testcontainers integration tests, and an OpenAPI contract test
- Redirect p95 latency under 50 ms at the application layer with a warm cache/DB under 200 requests/second
- Sustain at least 200 redirects/second and 20 shorten requests/second on a single instance
- Click recording must not add more than 5 ms to the redirect path (asynchronous write)
- Short codes are 7 characters of Base62 (~3.5 trillion combinations)
- Unit/integration test line coverage of at least 80% on service layer
- Application is stateless so multiple instances can run behind a load balancer
